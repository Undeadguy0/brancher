# Brancher — CLI утилита для git-push агента

---
Консольная утилита на Go (Cobra), которая в Git-проекте создаёт файл .branches с базовой структурой целей для всех удалённых репозиториев (remotes).
---

## Установка


```sh
    #Сборка (из корня репозитория)
    go build -o brancher .

    #Или установка в $GOPATH/bin
    go install github.com/Undeadguy0/brancher@latest

```
    

## Быстрый старт

``` sh
    #В корне Git-репозитория
    brancher
    
    #Указать другую директорию проекта
    brancher /path/to/project
    
    #Своя ветка по умолчанию вместо master
    brancher -b main
    
    #Принудительно использовать одну ветку для всех remotes
    brancher -f feature/new-feature
    
    #Перезаписать существующий .branches
    brancher -r
    
    #Тихий режим (нет предупреждений)
    brancher -s

    #То же самое, что brancher без подкоманды
    brancher init

    #Сменить ветку у цели
    brancher set origin develop

    #Добавить remote в git и цель в .branches
    brancher add gitlab git@gitlab.com:me/project.git

    #Удалить цель (и remote из git)
    brancher rm gitlab --git

    #Сверить .branches с git remote
    brancher list

    #Дописать цели для новых git remote
    brancher sync

```
    
## Использование
    
``` sh
    brancher [path] [flags]
    brancher <команда> [аргументы] [flags]
```
    
| Аргумент | Описание                                                     |
|----------|--------------------------------------------------------------|
| path     | Путь к корню Git-проекта (по умолчанию — текущая директория). Аналог -p; если указаны оба и они различаются — ошибка |

Если путь к проекту совпадает с именем подкоманды (например, папка `list`), используйте `-p list` или `./list`.

---

## Подкоманды

Все подкоманды работают с проектом из -p (а `init`, `list`, `sync` — ещё и из позиционного [path]); по умолчанию — текущая директория. Порядок целей в .branches сохраняется, новые цели дописываются в конец.

| Команда                             | Описание |
|-------------------------------------|----------|
| `brancher [path]`, `brancher init [path]` | Создать .branches для всех remote (флаги -f, -r) |
| `brancher set <remote> <branch>`    | Сменить ветку у существующей цели. Если цели нет — ошибка с подсказкой использовать add/sync |
| `brancher add <remote> [url] [branch]` | Если указан url — выполнить `git remote add <remote> <url>` (ошибка, если такой remote уже есть в git). Затем добавить цель. Ветка: [branch], иначе -f, иначе HEAD-ветка remote, иначе -b. Ошибка, если цель уже есть. Если .branches нет — он создаётся |
| `brancher rm <remote>`              | Удалить цель. С `--git` (`-g`) — также `git remote remove <remote>` |
| `brancher list [path]` (`ls`)       | Показать цели и сверить с `git remote`: помечает remote, которых нет в .branches, и цели, чьих remote уже нет в git |
| `brancher sync [path]`              | Дописать цели для git remote, которых нет в .branches. Существующие цели не меняются (флаг -f) |

Чтобы через `add` задать ветку для уже существующего git remote без url, используйте -f: `brancher add origin -f main`.

## Флаги
    
| Флаг             | Короткий | По умолчанию       | Где действует        | Описание                                                                       |
|------------------|----------|--------------------|----------------------|--------------------------------------------------------------------------------|
| --project        | -p       | текущая директория | везде                | Путь к корню целевого проекта                                                  |
| --default-branch | -b       | master             | везде                | Имя ветки, если HEAD-ветку remote определить не удалось                        |
| --silent         | -s       | false              | везде                | Не выводить предупреждения (например, про неизвестную HEAD-ветку)              |
| --force-branch   | -f       | пусто              | init, add, sync      | Использовать эту ветку вместо HEAD-ветки remote                                |
| --rewrite        | -r       | false              | init                 | Перезаписать .branches, если файл уже существует                               |
| --git            | -g       | false              | rm                   | Также удалить remote из git                                                    |

## Результат
    
В корне проекта создаётся файл .branches (JSON):

```json
    {
      "targets": [
        {
          "remote": "origin",
          "branch": "main"
        },
        {
          "remote": "upstream",
          "branch": "develop"
        }
      ]
    }
``` 
    
## Как работает
    
1. Определяет корень проекта — флаг -p, позиционный [path] или текущая директория
2. Проверяет .branches — если файл есть и нет флага -r, выходит с ошибкой
3. Получает список remotes — `git remote`. Если remotes нет, печатает сообщение и выходит с кодом 0, файл не создаётся
4. Для каждого remote:
   - С -f: использует ветку из флага -f
   - Без -f: берёт HEAD-ветку из локальной ссылки `git symbolic-ref refs/remotes/<remote>/HEAD` (она появляется после `git clone` или `git remote set-head <remote> -a`)
   - Если локальной ссылки нет — спрашивает remote: `git ls-remote --symref <remote> HEAD` (нужен доступ к remote)
   - Если HEAD-ветку определить не удалось, подставляет -b (по умолчанию master) и пишет предупреждение в stderr (кроме режима -s)
5. Собирает JSON (с отступом в 2 пробела) и атомарно записывает его в .branches (через временный файл и переименование)

Утилита не использует `sh`, `grep` и другие внешние программы, кроме самого `git`, поэтому одинаково работает в Windows и Linux.

## Примеры

``` sh
    #Базовое использование в текущем репозитории
    brancher
    
    #В другой папке, ветка по умолчанию — main, тихий режим
    brancher -p ~/projects/my-app -b main -s
    
    #Форсировать feature-ветку для всех remotes, перезаписать файл
    brancher -f feature/new-ui -r
    
    #В другом проекте, показать предупреждения, не перезаписывать
    brancher ~/work/other-project
```
    
    
    
    
    
## Коды выхода
    
| Код | Смысл                                                                     |
|-----|---------------------------------------------------------------------------|
| 0   | Успех (файл создан/обновлён, remotes нет — просто выходит, sync без изменений, list) |
| 1   | Ошибка (аргументы, git-ошибки — с текстом stderr git, JSON, запись файла, файл существует без -r, цель не найдена/уже есть в set/add/rm) |
