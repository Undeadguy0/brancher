# Brancher — CLI утилита для git-push агента

---
Консольная утилита на Go (Cobra), которая в Git-проекте создаёт файл .branches с базовой структурой целей для всех удалённых репозиториев (remotes).
---

## Установка


```sh
    #Сборка (из корня репозитория)
    go build -o brancher .

    #Или установка в $GOPATH/bin
    go install github.com/Undeadguy0/brancher@latest

```
    

## Быстрый старт

``` sh
    #В корне Git-репозитория
    brancher
    
    #Указать другую директорию проекта
    brancher /path/to/project
    
    #Своя ветка по умолчанию вместо master
    brancher -b main
    
    #Принудительно использовать одну ветку для всех remotes
    brancher -f feature/new-feature
    
    #Перезаписать существующий .branches
    brancher -r
    
    #Тихий режим (нет предупреждений)
    brancher -s

```
    
## Использование
    
``` sh
    brancher [path] [flags]
```
    
| Аргумент | Описание                                                     |
|----------|--------------------------------------------------------------|
| path     | Путь к корню Git-проекта (по умолчанию — текущая директория). Аналог -p; если указаны оба и они различаются — ошибка |
    
--- 
    
## Флаги
    
| Флаг             | Короткий | По умолчанию       | Описание                                                                       |
|------------------|----------|--------------------|--------------------------------------------------------------------------------|
| --default-branch | -b       | master             | Имя ветки по умолчанию, если у remote неизвестна HEAD-ветка                    |
| --project        | -p       | текущая директория | Путь к корню целевого проекта                                                  |
| --force-branch   | -f       | пусто              | Принудительно использовать эту ветку для всех remotes (игнорирует HEAD remote) |
| --silent         | -s       | false              | Не выводить предупреждения (например, про неизвестную HEAD-ветку)              |
| --rewrite        | -r       | false              | Перезаписать .branches, если файл уже существует                               |
    
---

    
## Результат
    
В корне проекта создаётся файл .branches (JSON):

```json
    {
      "targets": [
        {
          "remote": "origin",
          "branch": "main"
        },
        {
          "remote": "upstream",
          "branch": "develop"
        }
      ]
    }
``` 
    
## Как работает
    
1. Определяет корень проекта — флаг -p, позиционный [path] или текущая директория
2. Проверяет .branches — если файл есть и нет флага -r, выходит с ошибкой
3. Получает список remotes — `git remote`. Если remotes нет, печатает сообщение и выходит с кодом 0, файл не создаётся
4. Для каждого remote:
   - С -f: использует ветку из флага -f
   - Без -f: берёт HEAD-ветку из локальной ссылки `git symbolic-ref refs/remotes/<remote>/HEAD` (она появляется после `git clone` или `git remote set-head <remote> -a`)
   - Если локальной ссылки нет — спрашивает remote: `git ls-remote --symref <remote> HEAD` (нужен доступ к remote)
   - Если HEAD-ветку определить не удалось, подставляет -b (по умолчанию master) и пишет предупреждение в stderr (кроме режима -s)
5. Собирает JSON (с отступом в 2 пробела) и атомарно записывает его в .branches (через временный файл и переименование)

Утилита не использует `sh`, `grep` и другие внешние программы, кроме самого `git`, поэтому одинаково работает в Windows и Linux.

--- 
    
## Примеры

``` sh
    #Базовое использование в текущем репозитории
    brancher
    
    #В другой папке, ветка по умолчанию — main, тихий режим
    brancher -p ~/projects/my-app -b main -s
    
    #Форсировать feature-ветку для всех remotes, перезаписать файл
    brancher -f feature/new-ui -r
    
    #В другом проекте, показать предупреждения, не перезаписывать
    brancher ~/work/other-project
```
    
    
    
    
    
## Коды выхода
    
| Код | Смысл                                                                     |
|-----|---------------------------------------------------------------------------|
| 0   | Успех (файл создан или remotes нет — просто выходит)                      |
| 1   | Ошибка (аргументы, git-ошибки — с текстом stderr git, JSON-сериализация, запись файла, файл существует без -r) |
